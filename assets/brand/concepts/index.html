Step 1 · What makes a good product logo

Principles

  1. Simple, distinctive and appropriate, all three at once. Sagi Haviv (Chermayeff & Geismar & Haviv) names these as the three tests and says the work is balancing simple shapes against distinctive ones [1][2]. Simple alone gives you a generic mark; that is the problem with the current stacked layers.
  2. The doodle test. If someone can sketch it from memory after seeing it once, it is memorable [1]. A design-blog variant: show it for three seconds, hide it, ask what people saw [3].
  3. Design for 16 px first. A favicon, an npm avatar and a GitHub org avatar are tiny. Thin lines and small gaps vanish first; bold silhouettes survive. Scale it down to 16 × 16 and, if it blurs, draw a dedicated small version [4][3].
  4. Works in one colour. If it fails in solid black, colour won't save it [3]. Every concept below has a -mono file for this check.
  5. Light and dark. One SVG favicon can switch colour with a prefers-color-scheme media query inside it [4]; GitHub READMEs can swap images with <picture> [5]. Each concept has a -favicon file that does this.
  6. App icon: one focal shape, no text. Apple asks for a simple, bold image with a single focus that reads at every size, and now light, dark and tinted variants [6]. Square corners in the source; the OS rounds them.
  7. Meaning helps, but legibility comes first. A mark that tells the product's story is easier to remember and explain, but only once the silhouette works small.

Step 2 · What Bareship's logo should say

The brief

  • Bare. React Native CLI, no Expo. You own ios/ and android/; every native edit is marked. Nothing hidden.
  • Ship. "Bare React Native, ready to ship" is the reason for the name (ADR 0015). A ship, a hull or a sail is the obvious hook, and nautical marks are rare among JS tools.
  • Offline-first. Writes survive being offline and replay in order. This is Bareship's most distinctive feature and no peer logo shows it.
  • Rules for teams and AI agents. Architecture checked on every build: layers import downward only. The current mark's three layers come from this.
  • One command. npx create-bareship is the front door, and npm is where most people will first see the logo.

Constraints

  • Colour: keep the app's primary blue #0A6C96 (light) and #55B6E0 (dark) from src/shared/ui/theme/brands.ts and the website theme. All concepts use them, so a new logo needs no theme change.
  • Files: assets/brand/logo.svg (splash), icon.svg (app icon, square, no transparency), the website's light and dark logos and favicon.svg. pnpm icons and pnpm splash regenerate the native assets.
  • Where it appears first: the npm page and the README header at 96 px, the GitHub avatar, the browser tab at 16 px.
  • Avoid: stacks and layers (databases, cloud tools), React's atom (it belongs to React), anchors (they mean "stuck", the opposite of shipping).
