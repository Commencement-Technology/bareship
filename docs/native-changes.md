# Native changes

Every edit to `android/` or `ios/` beyond the React Native community template (0.87-stable) is listed here.
Two reasons: upgrades (re-apply these after the Upgrade Helper diff) and Track B (each row becomes an Expo
config plugin). Search the code for `[rn-template]` to find each change in place.

| Area | File(s) | Change | Why | Expo (Track B) equivalent |
| --- | --- | --- | --- | --- |
| <a id="android-flavors"></a>Android flavors | `android/app/build.gradle` | `environment` flavor dimension: dev (`.dev`), staging (`.staging`), prod. Per-flavor `app_name` via `resValue`. `debuggableVariants` lists the flavored debug variants. | Side-by-side installs per environment (ADR 0004) | `app.config.ts` per `APP_ENV`, or a flavors config plugin |
| <a id="android-env"></a>Android env values | `android/app/build.gradle` | Each flavor reads its own `.env.<flavor>` and adds every key as a `buildConfigField` + `resValue` (`applyEnvFile`). react-native-config's `dotenv.gradle` is **not** applied. `buildConfig = true`; `build_config_package` resValue | `dotenv.gradle` chooses one `.env` per Gradle run from the first task name, so `./gradlew assembleRelease` or `assembleDevDebug assembleProdRelease` baked dev values into the prod app (found 2026-10-10). CI checks each build with `scripts/ci/check-env.sh` | `app.config.ts` + `expo-constants` |
| Android strings | `android/app/src/main/res/values/strings.xml` | `app_name` removed (comes from the flavor) | Avoids a duplicate resource | n/a |
| Android release | `android/app/build.gradle`, `proguard-rules.pro` | R8 `minifyEnabled` + `shrinkResources` on; keep rule for `BuildConfig`; release signing from `RN_UPLOAD_*` properties or env vars, debug-key fallback with a warning | Smaller release builds; no keys in git | EAS credentials |
| Android icons | `android/app/src/<flavor>/res/mipmap-*` | Generated by `pnpm icons`; `main` has none | Badge per environment | `icon` per environment in `app.config.ts` |
| <a id="splash"></a>Splash (Android) | `MainActivity.kt`, `res/values/styles.xml`, `AndroidManifest.xml`, `res/drawable*/bootsplash_logo.png`, `res/values/colors.xml` | `RNBootSplash.init(this, R.style.BootTheme)` before `super.onCreate`; BootTheme set on the activity (generated by `pnpm splash`) | Native splash until JS is ready | `expo-splash-screen` |
| Splash (iOS) | `AppDelegate.swift`, `BootSplash.storyboard`, `Colors.xcassets`, `Images.xcassets/BootSplashLogo-*`, `Info.plist` | `customize(_ rootView:)` calls `RNBootSplash.initWithStoryboard`; `UILaunchStoryboardName = BootSplash`; template `LaunchScreen.storyboard` removed | Same | `expo-splash-screen` |
| iOS environments | `ios/Config/*.xcconfig`, `project.pbxproj`, `xcshareddata/xcschemes/*` | Six configurations (Debug/Release × Dev/Staging/Prod), each based on an xcconfig that includes the Pods xcconfig; schemes `<App>-Dev/-Staging/-Prod`; template Debug/Release and single scheme removed. Generated by `scripts/ios/configure-environments.rb` | Per-environment bundle id, display name and icon (ADR 0004) | `app.config.ts` per `APP_ENV` |
| <a id="uiscene"></a>iOS scene life cycle | `AppDelegate.swift`, `SceneDelegate.swift` (new), `Info.plist` (`UIApplicationSceneManifest`), `project.pbxproj` | The window and React Native start in a `UIWindowSceneDelegate`; `AppDelegate` only returns `true`. Cold-start URLs from `connectionOptions` are passed as launch options; runtime URLs and universal links are forwarded to `RCTLinkingManager`. The bootsplash hook moved here. | **Apps built with the iOS 27 SDK (Xcode 27) are killed at launch without the UIScene life cycle** ("UIScene life cycle is required for apps built with this SDK"). The RN 0.87 template still uses the app-delegate window; RN's `main` template has a SceneDelegate, backported here to 0.87 APIs | Handled by Expo's app delegate |
| iOS Swift DEBUG flag | `ios/Config/Debug-*.xcconfig`, `ios/Podfile` | `SWIFT_ACTIVE_COMPILATION_CONDITIONS = $(inherited) DEBUG` on the app's and the pods' `Debug-*` configurations | RN only sets it on a configuration named exactly `Debug`; without it `#if DEBUG` is false in `Debug-Dev` and the app looks for an embedded bundle instead of Metro ("No script URL provided") | n/a |

| iOS Podfile | `ios/Podfile` | `project` maps the six configurations to debug/release; post_install sets `ENVFILE` on the `react-native-config` pod per configuration | CocoaPods and react-native-config understand the custom configurations | n/a (managed by prebuild) |

## Planned (Phase 2)

- `android/build.gradle`: force every subproject onto the app's `ndkVersion`. react-native-unistyles does not read it
  and would otherwise pull in AGP 9's default NDK (28.2) next to RN's 27.1.
- `MainActivity.kt`: `supportFragmentManager.fragmentFactory = RNScreensFragmentFactory()` once react-native-screens
  (≥ 4.16) is installed, as react-native-bootsplash requires.
- Firebase: Google Services and Crashlytics Gradle plugins applied only when a flavor's `google-services.json`
  exists; iOS build phase copying `ios/Config/Firebase/<Env>/GoogleService-Info.plist` when present; static frameworks for Firebase pods.

## Known warnings

- iOS: `'RCTRootView' is deprecated` in `SceneDelegate.swift`. This comes from react-native-bootsplash's documented
  `customize(_ rootView:)` hook. Track the library's update; it is not an error.
- Re-check `SceneDelegate.swift` when upgrading to RN 0.88: its template ships an official SceneDelegate with
  `startReactNative(withModuleName:in:connectionOptions:)` and `RCTLinkingManager` scene helpers. Switch to those.
